Learning guide · basic to advanced

Follow a claim from first notice to final payment

Easy Claim is the InsureMO claims application. It runs a claim as a chain of tasks: report the loss, register it, investigate, assess the loss, collect documents, calculate, and settle. Each task has a page, a set of buttons and a rule that decides the next task. Approval tasks appear when an amount is above the user's authority.

Built from the InsureMO Easy Claim Function User Guide, including all of its screens, rules, screenshots and Q&A. Labels used in this guide:

Level 1

Foundations

What a claim is, the tasks that move it, the two claim modes, reserves, and the words and icons you will see on every screen.

What is a claim?

Claim is the whole process that starts when a risk event covered by an insurance contract happens. The insured or beneficiary asks the insurer for payment. The insurer reviews, investigates, assesses the loss, calculates the amount and pays according to the contract terms. Source

Easy Claim is a claim application built on the InsureMO Claim API. It gives standard workflows for insurance business and simplifies the claims process. Source

Why claims matter to the business. Claims are the largest cost line of an insurer. The claim reserve (money set aside for open claims) is a balance-sheet liability, and its accuracy drives reported profit, solvency and reinsurance recoveries. Speed of settlement drives customer retention. Domain context

Claim mode and sub-claim mode

Claim mode

One case holds everything

Traditional mode. One claim case contains all information. Used for property insurance, auto insurance and similar lines.

Sub-claim mode

One main case, many sub-cases

One main case can contain several sub-cases. Used for health insurance and for multiple claims under one event. Tasks can be created per sub-claim, based on the workflow configuration.

In both modes a claim has one or more sub-claims. A sub-claim is one damaged object or one person, for example a vehicle, a third-party property or a medical expense. Reserves, loss items, calculation rows and payments are all tied to a sub-claim and a coverage. Sub-claim numbers look like 001; in sub-claim mode the claim number carries the suffix, for example CFHI001202500001155-001. Screenshot

Reserve types seen on screens: Loss (Indemnity), Loss (Expense), Salvage (Expense), Subrogation. Screenshot

Reserve operations

  • Update — change the reserve amount.
  • Close — close the reserve.
  • Reopen — reopen a closed reserve.

Each operation can need an approval task: Reserve Update Approval, Reserve Close Approval, Reserve Reopen Approval. The Update, Close and Reopen buttons show only for users with the reserve permission set in claim authority configuration.

Reserve line columns: Sub-claim, Reserve Type, Coverage Name, Status (Open), Locked, Sum Insured, Outstanding Reserve, Settled. Screenshot

Reserve vs payment. A reserve is an estimate held on the books. It does not move money. Settlement moves money. When money is paid, the outstanding reserve goes down by the settled amount. Domain context In BCP, a reserve creates a fee record only (fee type 200201) for the GL, never a receivable or payable. BCP guide

Auxiliary tasks

These run next to the main line. You add them with New and Reopen > New Task.

Two kinds of task

Workflow task

FNOL, Registration, Investigation and the rest of the claim process. Find them in Claim > Claim Task. Each has an owner (a user or the shared pool), a status and a due date. When the due date passes, the work bench highlights the task.

Diary task

A reminder task. Create it by hand from the Diary Task link in the case summary, and assign it to a user. Find it in Claim > Diary Task.

The authority rule (the key pattern)

On a working task

When you submit Appraisal, Calculation, Settlement, Prepay, Subrogation or Salvage, the system compares the amount with your authority.

  • Within authority → the next task is created (or the task closes).
  • Above authority → an approval task is created.

On an approval task

The approver reads the same page in read-only mode and records a decision.

  • Reject → the original task comes back for rework.
  • Approve, within approver authority → the next task.
  • Approve, above approver authority → a new approval task for the next level.

This gives multi-level approval without extra screens. Authority amounts are set in claim authority configuration (InsureMO Claim API). See Level 2 for the simulator.

Level 5

Calculation and reserve logic

The most technical part of Easy Claim. Two calculation engines exist side by side, and the choice changes how repeat calculations, settlement and reserve closing behave.

What changed and why

Claim requirements grew more complex across product lines, so InsureMO updated the APIs and claim configuration in three areas:

1. New calculation tool

Replaces the built-in rating function of GIMO. Use it to configure the formulas and logic for claim calculation.

2. Claim Matrix V2

A new Claim Matrix version that supports product configuration with the new calculation rules.

3. Full-scale calculation

The latest calculation holds the total amount, not the increment. This also allows parallel tasks based on full-scale calculation.

The update does not change existing functions. Default and existing calculation rules stay the same. Parameters control the behaviour, and tenants who stay on the current version need no extra configuration. Source

Reserve close validation checker

With the new tool, closing a reserve runs an extra check: if the paid amount is not 0 and the settled amount differs from the calculation amount, the system shows a validation message. With GIMO rating, the old validation stays.

Reserve mechanics

Where reserves are touched

  • Registration — add reserve lines (Add, delete).
  • Investigation, Appraisal — Update, Close, Reopen, Reserve Summary, Reserve History.
  • Case Information — Reserve History and Update.
  • New Subclaim — add reserve for the new sub-claim only; existing reserve is read-only.
  • Approval tasks — Reserve Update / Close / Reopen Approval show Change Amount, New Outstanding Reserve, Settled. Screenshot

Reserve arithmetic Domain context

  • Outstanding reserve = expected total cost − paid so far.
  • Incurred = paid + outstanding. Management and reinsurers watch incurred.
  • A settlement reduces outstanding by the settled amount. A final settlement normally brings it to 0 and closes the reserve.
  • Recoveries (salvage, subrogation) reduce the net incurred cost.
  • Reserve changes above authority need approval because they change the reported liability.
